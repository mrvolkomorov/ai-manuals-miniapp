n8n: автоматизация редакционной рутины

От регистрации до первого робота · v1.0 · 23.09.2026 · Курс ИИ-инструменты для региональной редакции
На втором занятии мы не успели дойти до n8n. Этот документ закрывает пробел: пройдите его в своём темпе — от регистрации до первого робота, который сам приносит новости.

1. Коротко: чем n8n отличается от агента

Агент (LobeHub и аналогичные приложения) — это диалог. Вы пишете задачу — он её делает «сейчас». n8n — это робот, который работает без вас: по расписанию или по событию, в фоне.

Агентn8n
ЗапускВы пишете в чатСам: по расписанию или событию
ЗадачаРазовые, творческиеПовторяющиеся, конвейерные
Участие человекаНужноНе нужно после настройки
Что делаетИщет, пишет, анализируетСобирает → обрабатывает → доставляет

Что реально закрывает n8n в редакции:

  • 08:00 — утренний дайджест из 10 каналов в рабочий Telegram
  • Мониторинг упоминаний города и холдинга → алерт в чат
  • Кросс-постинг: один материал → посты в VK / Telegram / OK / Дзен
  • Логирование всего найденного в Google-таблицу
  • Пятничная сводка статистики каналов

2. Что понадобится

  • Аккаунт n8n (облако или свой сервер)
  • Telegram-бот и его токен (делается за 2 минуты через @BotFather)
  • Ключ API модели (DeepSeek / OpenRouter / AiTunnel — те же, что в LobeHub)
  • Доступ к TGStat (если делаете мониторинг каналов)
  • Google-аккаунт (для таблиц-логов)
  • 30–60 минут на первый запуск

4. Анатомия n8n за 3 минуты

  • Canvas — рабочее поле
  • Node — блок. Жёлтый — триггер, остальные — действия
  • Trigger — расписание, вебхук, новое письмо, новая публикация
  • Action — HTTP-запрос, Telegram, Google Sheets и т.д.
  • LLM — модель для анализа и текста (через HTTP Request)
  • Credentials — ключи и токены (хранятся в n8n, а не в тексте workflow)
  • Execute / Test — пробный запуск
  • Active — переключатель «работать по расписанию»

5. Шаг 1. Регистрация в n8n Cloud

  1. Откройте n8n.cloud → Sign up
  2. Email + пароль → подтвердите письмо
  3. Выберите триал (14 дней, карта не нужна)
  4. Откроется редактор (холст)
✅ Признак успеха: видите пустой холст и кнопку «Add first step…»

6. Шаг 2. Первый workflow за 5 минут

Цель — понять механику. Соберём робота, который «просыпается» по расписанию.

  1. Add first step → Schedule Trigger
  2. В параметрах: Trigger Interval = Minutes, Minutes Between Triggers = 10 (для теста)
  3. Add node → Code → вставьте:
return [{ json: { message: "Привет от n8n! " + new Date().toLocaleString() } }];
  1. Нажмите Execute Workflow
  2. Посмотрите результат в ноде Code (таблица с полем message)
⚠️ Workflow не запускается сам, пока вы не нажмёте Active (вверху справа). На триале активация расписания может быть недоступна — для учёбы достаточно кнопки Execute.
💡 Не хотите трогать Code-ноду? В тарифе Cloud с AI-ассистентом просто опишите робота словами — ассистент сам расставит Schedule Trigger и действия. Code нужен, чтобы понимать механику, но для рабочего робота он не обязателен.

7. Шаг 3. Подключаем Telegram-бота

  1. В Telegram: @BotFather → /newbot → придумайте имя → получите токен вида 123456:AA...
  2. В n8n: Add node → Telegram → Create credentials → вставьте токен → Save
  3. Узнайте свой chat_id: напишите боту @userinfobot — он пришлёт ваш id
  4. Настройте ноду Telegram: Resource = Message, Operation = Send Message, Chat ID = ваш id, Text = {{ $json.message }}
  5. Execute → сообщение должно прийти в Telegram
⚠️ Если бот пишет «chat not found» — сначала напишите своему боту /start, потом снова Execute.
⚠️ Для публикации в канал добавьте бота админом в канал и используйте chat_id канала (например, -1001234567890).

8. Шаг 4. Подключаем модель (LLM)

Модель подключается двумя путями: через HTTP Request (универсально и наглядно) или готовыми AI-нодами — в Cloud их расставит AI-ассистент.

💡 В Cloud с AI-ассистентом этот шаг можно не собирать руками: напишите ему «добавь ноду для LLM, подключи DeepSeek по моему ключу». Ручной HTTP Request всё равно стоит пройти: видно, что происходит внутри запроса, и такая же цепочка работает и в Cloud, и на своём сервере.
  1. Add node → HTTP Request
  2. Method = POST, URL = https://api.deepseek.com/chat/completions (или endpoint вашего агрегатора — OpenRouter, AiTunnel)
  3. Authentication = Generic Credential Type → Header Auth → Name: Authorization, Value: Bearer ВАШ_КЛЮЧ
  4. Send Body = JSON:
{
  "model": "deepseek-chat",
  "messages": [
    { "role": "system", "content": "Ты редактор региональной редакции. Отбери 3 главные новости и дай анонс по 2 предложения." },
    { "role": "user", "content": "{{ $json.posts }}" }
  ]
}

Ответ модели лежит в {{ $json.choices[0].message.content }} — передайте его в ноду Telegram.

⚠️ Ключи и токены держите в Credentials, а не в тексте URL или body. Не публикуйте скриншоты с ключами.

9. Шаг 5. Рабочий сценарий: «Утренний дайджест редакции»

Логика: Schedule (08:00) → источник постов → LLM (отбор + анонсы) → Telegram (в чат редакции) → Google Sheets (лог).

  • Schedule: Trigger Interval = Days, Hour = 8
  • Источник — один из двух:
    А (проще): RSS/HTTP к сайтам городских властей и конкурентов;
    Б (как на занятии): HTTP к вашему Telegram MCP / TGStat MCP (URL Railway + /mcp)
  • LLM: как в шаге 4 — отбор и анонсы
  • Telegram: отправка в рабочий чат
  • Google Sheets: Add node → Google Sheets → Append Row (логируем дату, тему, источник, ссылку)
  • Execute → проверьте цепочку → Active

10. Демо-сценарий: «Мониторинг каналов + алерт»

Готовый шаблон из демо (собирать руками не нужно — импортируйте):

Schedule (каждые 2 часа) → HTTP (Telegram/TGStat MCP: последние посты по ключевым словам) → LLM (классификатор: релевантно/нет + анонс) → Filter (только релевантное) → Telegram Bot (алерт) → Google Sheets (лог)

Что заменить под себя: город, ключевые слова, chat_id, ключи.

Как импортировать workflow

  1. Скачайте JSON-файл шаблона (или скопируйте текст)
  2. n8n → вверху справа «…» → Import from File (или Import from Clipboard)
  3. Откроется холст с нодами
  4. Откройте каждую ноду с 🔴 (не настроена) → подставьте свои ключи / url / chat_id
  5. Execute для теста → Activate

Минимальный JSON-шаблон (для тренировки)

{
  "name": "Мой первый робот",
  "nodes": [
    {
      "parameters": { "rule": { "interval": [ { "field": "minutes", "minutesInterval": 10 } ] } },
      "id": "1",
      "name": "Schedule Trigger",
      "type": "n8n-nodes-base.scheduleTrigger",
      "typeVersion": 1.2,
      "position": [240, 300]
    },
    {
      "parameters": { "jsCode": "return [{ json: { message: 'Привет от n8n! ' + new Date().toLocaleString() } }];" },
      "id": "2",
      "name": "Code",
      "type": "n8n-nodes-base.code",
      "typeVersion": 2,
      "position": [460, 300]
    }
  ],
  "connections": { "Schedule Trigger": { "main": [ [ { "node": "Code", "type": "main", "index": 0 } ] ] } },
  "active": false,
  "settings": {},
  "versionId": "1",
  "meta": {},
  "tags": []
}
🔁 Тот же JSON-файл потом импортируется в n8n на своём сервере: цепочка, собранная в Cloud, продолжает работать на VPS за ~800 ₽/мес (раздел 15).

11. Экономика: как не сжечь лимит

  • Не ставьте расписание чаще, чем нужно (раз в день или час, а не каждые 5 минут)
  • Триггер «по событию» дешевле расписания — запуск только когда есть новость
  • Тестируйте кнопкой Execute, а не Active
  • Держите LLM-запросы короткими; черновой отбор делайте без модели (Filter по ключевым словам), а модель зовите только для анонсов

12. Безопасность

  • Credentials — только внутри n8n. Не вставляйте ключи в Code/URL, которые потом кому-то покажете
  • URL вашего Telegram MCP — персональный. Кто его знает, может читать и отправлять сообщения от вашего имени. Не публикуйте его
  • Заведите отдельный бот для редакции, не личный
  • Не гоняйте через n8n персональные данные и закрытые документы без обезличивания
  • Перед Activate проверьте, куда уходит результат (в какой чат, какую таблицу)

15. ⭐ Задание со звёздочкой: n8n на своём сервере (~800 ₽/мес)

Это необязательный шаг — но самый выгодный. Он сложнее остальных, зато решается за один вечер: раз подняв свой сервер, вы перестаёте платить за подписку.

Зачем это делать

  • Cloud — €24/мес (≈2 300–2 400 ₽), свой VPS — ≈800 ₽/мес. Разница почти втрое
  • Нет лимита на 2 500 запусков: расписание «каждые 5 минут» перестаёт быть проблемой
  • Данные и черновики остаются на вашем сервере, а не в облаке ЕС — для редакции это плюс

Путь: собрать в Cloud → перенести на VPS

  1. В n8n Cloud с AI-ассистентом соберите рабочие цепочки (дайджест, мониторинг, кросс-постинг)
  2. Экспортируйте каждую: «…» → Download — получится JSON-файл workflow
  3. Арендуйте VPS за ~300–600 ₽/мес
  4. Разверните self-hosted n8n: официальный образ n8nio/n8n и одна команда docker run (либо docker-compose)
  5. Откройте свой n8n по адресу сервера → Import from File → выберите JSON из шага 2
  6. Заново впишите credentials: токены и ключи в Cloud и на своём сервере хранятся независимо — автоматически они не переносятся
  7. Проверьте Execute → включите Active

Что понадобится и что помнить

  • Базовое умение скопировать команду в терминал, 1–2 часа времени, аккаунт у хостинг-провайдера
  • Если страшно — попросите IT-отдел: для системного администратора это задача на 20 минут
  • Лимитов запусков нет, но есть лимиты сервера: следите за диском и памятью
  • Раз в 1–2 месяца обновляйте образ docker — это исправления безопасности
  • Раз в неделю выгружайте бэкап (workflow + база n8n), чтобы не потерять настройки
Когда это оправдано: если роботов больше двух или расписание частое — лимит Cloud (2 500 запусков) сгорит за недели, и self-hosted окупается сразу.
